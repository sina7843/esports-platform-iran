# پشتیبان‌گیری، بازیابی و نگهداری داده (NFR-007, OPS-001..004, SEC-004)

## اهداف
RPO ≤ ۱۵ دقیقه، RTO ≤ ۲ ساعت (NFR-007)؛ تطبیق مالی پس از بازیابی الزامی؛ پشتیبان رمزگذاری‌شده در دامنه خرابی مستقل از اصلی (داخل ایران). این‌ها هدف پذیرش‌اند و با تمرین بازیابی (AC-22، ESP-07) اثبات می‌شوند.

## چه چیزی پشتیبان می‌گیریم
| داده | روش | تناوب |
|---|---|---|
| MongoDB (replica set `rs0`) | `mongodump --oplog` از secondary/hidden member + آرشیو oplog پیوسته برای point-in-time | snapshot کامل روزانه + oplog هر ≤ ۱۰ دقیقه |
| فایل‌های خصوصی/عمومی (`DATA_DIR/private-files`, `public-files`, `quarantine`) | همگام‌سازی افزایشی به object storage یا سرور داخلی دوم | هر ≤ ۱۵ دقیقه |
| پیکربندی و keyfile | فقط در مخزن اسرار عملیات (خارج از عامل) | هنگام تغییر |

## رمزگذاری
بسته‌های پشتیبان پیش از خروج از میزبان با `age`/GPG (کلید عمومی تیم عملیات) رمزگذاری می‌شوند؛ کلید خصوصی خارج از زیرساخت اصلی نگهداری می‌شود. دیسک پایگاه داده و storage در تولید باید encryption-at-rest فراهم‌شده توسط میزبان ایرانی داشته باشد (SEC-004).

## بازیابی (رویه)
1. اعلام رخداد و توقف نوشتن (worker و api در حالت maintenance).
2. بازگردانی آخرین snapshot + replay oplog تا نقطه هدف (`mongorestore --oplogReplay`).
3. بازگردانی فایل‌ها تا همان نقطه.
4. اجرای `pnpm db:migrate status` (نباید pending باشد) و `GET /ops/audit/verify` (زنجیره باید سالم باشد).
5. **تطبیق مالی**: فهرست پرداخت‌های `awaiting_gateway/unknown` در بازه از‌دست‌رفته با مرجع درگاه تطبیق داده می‌شود (ESP-03 ابزار reconcile را می‌سازد)؛ رخدادهای outbox `processing` با lease منقضی به‌طور خودکار دوباره برداشته می‌شوند.
6. بازگشایی و ثبت گزارش (RPO/RTO واقعی).

تمرین بازیابی حداقل فصلی در محیط آزمایش (OPS-004)؛ نتیجه در `IMPLEMENTATION_STATUS.md` ثبت می‌شود.

## نگهداری و حذف (OPS-001..003)
| دسته | پیشنهاد نگهداری | پیاده‌سازی |
|---|---|---|
| نتیجه، ترکیب تاریخی، نسخه قوانین، افتخار | عمر سرویس | بدون TTL |
| مدارک اعتراض (`dispute_evidence`) | ۱۲ ماه پس از بسته‌شدن | `retentionClass` روی فایل؛ job حذف در ESP-07 با احترام به hold |
| دمو (`demo`) | ۹۰ روز پس از قطعیت | همان |
| لاگ عملیاتی | ۹۰ روز | چرخش لاگ میزبان |
| ممیزی حساس (`audit_log`) | ۲۴ ماه | بدون حذف خودکار؛ آرشیو رمزگذاری‌شده |
| رخدادهای realtime | ۷ روز | TTL index |
| نشست‌های منقضی | ۳۰ روز پس از انقضا | TTL index |
| اسناد هویتی/مالی | **تا تصویب سیاست جمع‌آوری نمی‌شود** (OPS-002) | `identity_document` مسدود در `Files.upload` |

پرونده باز، دستور نگهداری (legal hold) و الزام قانونی بر حذف زمان‌بندی‌شده مقدم‌اند؛ job حذف باید پیش از حذف، hold را بررسی کند. کاربر پیش از ارسال فایل اعلان فارسی مدت نگهداری (`retentionNoticeFa`) را می‌بیند. حذف از سامانه اصلی بلافاصله و از نسخه‌های پشتیبان با چرخه نگهداری پشتیبان (حداکثر ۹۰ روز) انجام می‌شود.

## محیط‌ها (OPS-005)
local / ci / staging / production با `APP_ENV`؛ داده واقعی بدون ناشناس‌سازی وارد staging نمی‌شود؛ seed فقط `TEST ONLY` و در production اجرا نمی‌شود.

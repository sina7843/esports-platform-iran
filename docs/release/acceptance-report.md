## نیازمندی‌های غیرعملکردی NFR-001..011
### بار (NFR-001..004، AC-21)
اجرای ۶۰ دقیقه‌ای بار هدف: `evidence/load-target-60min.json`.

| معیار | هدف | اندازه‌گیری |
|---|---|---|
| نشست | ۱۰٬۰۰۰ | ۱۰٬۰۰۰ نشست با Bearer، هرکدام درخواست‌های واقعی زد |
| رویارویی جاری | ۳۰۰ | ۳۰۰ بازی در وضعیت live در پایگاه |
| عامل اجرایی | ۱۰۰ | ۱۰۰ اپراتور با نقش برگزارکننده، نمایش داشبورد/ops |
| نرخ | ۵۰۰ rps، ۸۰/۲۰ | ۵۰۰ ثابت (open-loop)؛ ۱٬۷۹۹٬۹۹۹ درخواست در ۳۶۰۰ ثانیه؛ ۲۰٪ نوشتن (chat) |
| پایداری ۶۰ دقیقه | خطا < ۱٪، بدون از دست رفتن عملیات تأییدشده | خطا **۰٪** (همه ۲۰۰)؛ ۳۶۰٬۶۹۲ نوشتن تأییدشده = ۳۶۰٬۶۹۲ ردیف در پایگاه؛ dead-letter صفر |
| p95 خواندن | ≤ ۸۰۰ ms | بدترین گروه خواندن **۱۳۶ ms** (داشبورد اپراتور؛ سایر گروه‌ها ≤ ۷۸ ms)؛ p99 تا ۷۱۳ ms |
| p95 نوشتن | ≤ ۱٬۵۰۰ ms | **۱۵۰ ms** (p99 ۴۸۴ ms) |

محدودیت‌ها (صادقانه): یک ماشین، api تک‌پردازه، mongo یک‌عضوی؛ اجرا هم‌زمان با آزمون‌ها و آزمایشگاه مرورگر روی همان ماشین بود (نتیجه محافظه‌کارانه است، اما کنترل‌شده نیست)؛ ۱۰ هزار اتصال SSE هم‌زمان و fan-out زنده باز نشد؛ زمان سرویس بیرونی جدا اندازه‌گیری نشد (هیچ ارائه‌دهنده‌ای نیست). یافته‌ای که در مسیر کشف شد: بدون محافظ، ۵۰۰ rps یک پردازه را با کمبود حافظه از کار انداخت (D-060) و رفع شد؛ اجرای بعدی بدون خطا بود.

### بازیابی (NFR-007، AC-22)
- تمرین روی پایگاه ۲۴۵٬۰۰۰ سندی: پشتیبان ۶٫۹ ثانیه، بازیابی ۲۳٫۹ ثانیه، **RPO بدترین‌حالت ۱۰٫۱ دقیقه** (فاصله ۱۰ دقیقه + مدت اجرا؛ هدف ≤ ۱۵)، **RTO اندازه‌گیری‌شده ۰٫۵ دقیقه** (هدف ≤ ۲ ساعت؛ بدون زمان تأمین میزبان جایگزین و واکنش انسانی). یکپارچگی (امضا/هش/رمزگشایی کامل)، شمار اسناد، زنجیره حسابرسی، توازن دفتر کل و بازپخش صف: سبز.
- تطبیق مالی با پرداخت واقعی: آزمون `ops/backup.test.ts` «drill with a real paid registration» (پرداخت تأییدشده ↔ ثبت دفتر کل پس از بازیابی) سبز.
- یافته: تمرین روی پایگاه smoke قدیمی (`backup-drill-2026-10-21T00-19-08-275Z.json`) شکسته‌بودن زنجیره حسابرسی منبع را در seq 471 گزارش کرد؛ علت یک رقابت در `AuditLog.append` بود که رفع شد (D-067) و آزمون رقابت دارد. پایگاه‌های قدیمی پیش از رفع ممکن است زنجیره شکسته داشته باشند.
- دفتر حذف‌ها بیرون از پشتیبان نگه‌داری می‌شود تا داده حذف‌شده با بازیابی نسخه قدیمی برنگردد.

### داده زنده (NFR-005) — نیازمند شاهد
پل realtime میان worker و api (۵۰۰ms) و micro-cache ۲ ثانیه؛ آزمون نشان می‌دهد انتشار بین پردازه‌ها کمتر از ۱ ثانیه است. p95 سرتاسری تا نمایش در مرورگر در بار هدف اندازه‌گیری نشد.

### دسترس‌پذیری سرویس (NFR-006) — مسدود عملیاتی
۹۹٫۹٪ ماهانه فقط با یک ماه عملیات واقعی قابل اندازه‌گیری است.

### تجربه صفحه (NFR-008) و دسترس‌پذیری رابط (NFR-009)، سازگاری (NFR-010) — نیازمند شاهد
آزمایشگاه Chrome 155 (headless)، نسخه تولید، با شبیه‌سازی 4G و CPU ۴×، ۲۵ صفحه × ۲ پروفایل = ۵۰ اجرا با نقش مجاز هر مسیر (ریدایرکت و صفحه خالی ثبت می‌شود: ۰):
- axe (WCAG 2.0/2.1/2.2 A+AA): **۰ تخلف** پس از رفع.
- LCP موبایل: میانه ۱٫۱ ثانیه، p75 ۲٫۲ ثانیه، بیشینه ۲٫۷؛ دسکتاپ ≤ ۰٫۱۶ ثانیه (سرور محلی).
- CLS: ≤ ۰٫۱ همه جا جز `/admin/ops` (۰٫۱۹)، `/organizer` (۰٫۱۳)، `/events/:id/live` موبایل (۰٫۱۳) و `/games` دسکتاپ (۰٫۱۰۵) — **باز**.
- بدون سرریز افقی، همه صفحه‌ها `lang=fa dir=rtl`، بدون خطای کنسول؛ کاوش صفحه‌کلید: فوکوس‌پذیر با نشانگر مشاهده‌پذیر.
- **داده میدانی وجود ندارد؛ INP اندازه‌گیری نشد؛ فقط Chrome؛ دستگاه واقعی و screen reader بررسی نشد.** این‌ها داده آزمایشگاهی‌اند و جای p75 کاربر واقعی را نمی‌گیرند.
- یافته مهم این بازبینی: قاعده‌های CSS با `:global()` در نسخه تولید کل صفحه را آینه/جابه‌جا می‌کردند (روی موبایل خارج از صفحه)؛ رفع شد و آزمون محافظ دارد (D-065). نتایج axe پیش از رفع روی صفحه‌های خالی/۴۰۳ بود و معتبر نبود؛ آزمایشگاه اصلاح شد.

### مقیاس‌پذیری (NFR-011) — نیازمند شاهد
api و worker بی‌حالت‌اند و پل realtime وجود دارد؛ مقیاس با بیش از یک replica آزموده نشد؛ سهمیه و circuit breaker در هر پردازه است.

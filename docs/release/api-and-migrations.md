# API شریک (v1) و مهاجرت‌ها

## API مرورگر/داخلی
قرارداد کامل OpenAPI: `docs/api/openapi.json` (خروجی `pnpm docs:generate`). خطاها همیشه `{ error: { code, message, requestId, details? } }` بدون stack یا راز. پیشوند `/api/v1`. اضافه‌شده در ESP-07: `/admin/*` (کاربران، وظایف، تیکت، اقدام گروهی، تنظیمات، حریم خصوصی، نگهداری، ارائه‌دهنده‌ها، مشتریان API، گزارش‌ها، سلامت)، `/support/*`، `/privacy/*`، `/legal/*`، `/ops/metrics`.

## API عمومی/شریک — `/partner/v1`
بدون کوکی و بدون CSRF؛ هر درخواست امضا می‌شود. نسخه در مسیر و هدر پاسخ `x-esp-api-version: v1`. پاسخ‌ها `cache-control: private, no-store`.

### احراز هویت
هدرها: `x-esp-key` (شناسه کلید)، `x-esp-timestamp` (میلی‌ثانیه، حداکثر ±۵ دقیقه)، `x-esp-nonce` (۱۲–۸۰ نویسه، یکبارمصرف)، `x-esp-signature`:

```
signature = HMAC-SHA256(secret, timestamp + "\n" + nonce + "\n" + METHOD + "\n" + pathWithQuery + "\n" + sha256hex(bodyBytes))
```
(مقدار hex). بدنهٔ امضاشده همان بایت‌های ارسالی است. nonce تکراری در ۱۵ دقیقه رد می‌شود (replay)، سهمیه در دقیقه برای هر مشتری اعمال می‌شود (۴۲۹)، همه تلاش‌های ناموفق و موفق حسابرسی می‌شوند (بدون راز). راز هنگام ساخت یا چرخش فقط یک بار نشان داده می‌شود؛ ابطال فوری است.

### دامنه‌ها (scopes) و داده
| مسیر | scope | یادداشت |
|---|---|---|
| `GET /events` | `events:read` | فقط رویدادهای عمومی؛ اگر مشتری فهرست رویداد دارد فقط همان‌ها |
| `GET /events/:id/results` | `results:read` | همان سیاست انتشار سایت: نمای هماهنگ با پخش و تأخیر؛ `view=latest` پذیرفته نمی‌شود و به نمای تأخیردار تبدیل می‌شود؛ نتیجه موقت برچسب موقت دارد |
| `GET /events/:id/news` | `news:read` | خبرهای منتشرشده با رعایت تأخیر |
| `GET/POST/DELETE /webhooks` | `webhooks:manage` | حداکثر ۱۰ وب‌هوک فعال برای هر مشتری |

### وب‌هوک
رویدادهای مجاز: `competition.match.finalized`, `competition.event.finished`, `competition.event.closed`, `honors.issued`, `competition.result.corrected`. نشانی باید https و عمومی باشد (محافظ SSRF: آدرس خصوصی/loopback/link-local/multicast و credential در URL رد می‌شود، هنگام ثبت و دوباره هنگام هر ارسال). ارسال: `POST` با `x-esp-delivery` (شناسه یکتای تحویل = idempotency)، `x-esp-timestamp`، `x-esp-signature = HMAC(webhookSecret, timestamp + "." + body)`. هر (وب‌هوک، رویداد) فقط یک تحویل دارد. تحویل برای رویداد دارای تأخیر پخش، تا گذشتن تأخیر منتظر می‌ماند. تلاش مجدد: ۶ بار با فاصله ۳۰ ثانیه، ۲، ۱۰ دقیقه، ۱، ۴، ۱۲ ساعت؛ سپس «مرده» و قابل ارسال دوباره توسط اپراتور. پاسخ غیر ۲xx یا timeout (۵ ثانیه) شکست است؛ ریدایرکت دنبال نمی‌شود.

## مهاجرت‌ها (migrations)
افزایشی، با checksum و بدون ویرایش مهاجرت اجراشده؛ تغییر جدید = مهاجرت جدید.

| شناسه | محتوا |
|---|---|
| 0001 | ایندکس‌های پایه |
| 0002–0005 | هویت، تیم، کاتالوگ، قوانین، یکتایی عضویت و درخواست سازمان، backfill |
| 0006–0007 | رویداد، ثبت‌نام، مالی، اشتراک |
| 0008 | موتور رقابت و عملیات |
| 0009 | نتایج، یکپارچگی، رتبه‌بندی، افتخارات |
| 0010 | زنده، خبر، پخش، جامعه (حذف TTL لحظه‌ای به نفع job نگهداری) |
| 0011 | ESP-07: وظایف/تیکت/گروهی/تنظیمات، متن‌های حقوقی و رضایت، درخواست داده، سیاست نگهداری (پیش‌فرض‌های پیشنهادی؛ اسناد هویتی و مالی تأییدنشده)، توقیف‌ها، دفتر حذف، پشتیبان، ثبت ارائه‌دهنده، مشتریان شریک و nonce (TTL ۹۰۰ ثانیه)، وب‌هوک و تحویل یکتا |

اجرا: `pnpm db:migrate` (یا خودکار هنگام شروع api/worker). سازگاری عقب‌رو: نسخه قبلی کد با طرح جدید کار می‌کند چون فقط فیلد/کلکسیون/ایندکس اضافه شده است.

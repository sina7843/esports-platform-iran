# کاوه‌نگار — پیامک واقعی و کد ورود

اتصال از مستند رسمی https://kavenegar.com/rest.html پیاده شده است. رابط شماره/کد و کارت مدیریت با الگوهای دریافت‌شده از MCP رسمی VibeFarsi (`get_design_rules`, `get_component`: phone-input, otp-field, alert, card) به Vue تطبیق داده شده‌اند. MCP ابزار طراحی است؛ ارسال واقعی از بک‌اند و REST API کاوه‌نگار انجام می‌شود.

## فعال‌سازی روی سرور

در پنل کاوه‌نگار حساب دارای اعتبار و دسترسی Verify Lookup آماده کنید. یک الگوی تأییدشده با متغیر `%token` بسازید، مثلاً نام `EsportsOtp` و متن عمومی «کد تأیید شما: %token». از الگوی مخصوص «ورود» برای تأیید شماره/احراز مجدد با متن گمراه‌کننده استفاده نکنید؛ همین الگو برای همه چالش‌های پیامکی استفاده می‌شود.

در متغیرهای محیطی API و worker (در Coolify، Environment Variables) تنظیم کنید:

```dotenv
SMS_ADAPTER=kavenegar
KAVENEGAR_API_KEY=<secret-from-your-account>
KAVENEGAR_OTP_TEMPLATE=EsportsOtp
# فقط برای پیامک خدماتی غیر OTP، در صورت نیاز:
KAVENEGAR_SENDER=<your-service-sender>
```

کلید واقعی را در git، مرورگر، فایل نمونه یا پیام چت قرار ندهید. بعد از تغییر متغیرها سرویس‌ها را دوباره راه‌اندازی کنید. `compose.coolify.yaml` این متغیرها را به هر دو سرویس منتقل می‌کند؛ compose تولید از `.env` واقعی می‌خواند. راه‌اندازی با `SMS_ADAPTER=kavenegar` و کلید/الگوی خالی عمداً متوقف می‌شود.

## ثبت ارائه‌دهنده و شبکه

در `/admin/integrations` کارت «پیامک کاوه‌نگار» وضعیت تنظیمات را بدون نمایش کلید نشان می‌دهد. «آماده‌سازی فرم کاوه‌نگار» اطلاعات رسمی را فقط در فرم قرار می‌دهد؛ نتیجه آزمون را جعل و ارائه‌دهنده را خودکار انتخاب نمی‌کند.

1. فرم را ذخیره کنید، محدودیت/هزینه/مرجع شرایط و طرح خروج را تکمیل کنید.
2. ارزیابی حساب و الگوی تأییدشده را انجام دهید و نتیجه واقعی را ثبت کنید؛ سپس ارائه‌دهنده را انتخاب کنید.
3. دامنه انتخاب‌شده باید دقیقاً `https://api.kavenegar.com` باشد. بدون ردیف sms انتخاب‌شده با این origin، حتی اتصال حساب از سرور رد می‌شود.
4. وضعیت اتصال را به‌روز کنید: این درخواست فقط `account/info` را می‌خواند و هیچ پیامکی نمی‌فرستد. پاسخ سلامت حداکثر یک دقیقه cache می‌شود. موفقیت حساب به معنی تأیید الگو یا دریافت پیامک نیست.
5. با شماره متعلق به خودتان ورود واقعی را آزمایش کنید: درخواست کد، دریافت، تأیید، ارسال مجدد پس از مهلت، کد اشتباه و منقضی‌شده. این آزمایش نیازمند اعتبار حساب است؛ آزمون‌های مخزن پیامک واقعی ارسال نمی‌کنند.

کاوه‌نگار فقط یکی از پیش‌نیازهای production را برطرف می‌کند. تا تکمیل سایر الزامات، پروفایل آزمایشی Coolify را production اعلام نکنید. در زمان انتقال نهایی، ورود توسعه‌ای را با `AUTH_DEV_LOGIN_ENABLED=false` خاموش کنید و حساب مدیر/MFA را از قبل آماده داشته باشید.

## رفتار و محدودیت‌ها

- OTP با `verify/lookup`، `type=sms` و token صریح ارسال می‌شود؛ کد از متن فارسی استخراج نمی‌شود. برای OTP شماره فرستنده لازم نیست.
- شماره فارسی/لاتین/+98/0098 به شماره محلی ۱۱ رقمی تبدیل می‌شود؛ کد شش‌رقمی با صفر ابتدایی معتبر است.
- پیام خدماتی از `sms/send` و فرستنده تنظیم‌شده استفاده می‌کند؛ `localid` عددی پایدار از idempotencyKey برای جلوگیری از تکرار ساخته می‌شود. پیامک تبلیغاتی در این اتصال غیرفعال است.
- درخواست POST با HTTPS، origin ثابت، ممنوعیت redirect و timeout واقعی؛ خطای شبکه یا پاسخ مبهم خودکار دوباره ارسال نمی‌شود. پذیرش در صف به معنی تحویل قطعی نیست؛ وضعیت تحویل از `sms/status` خوانده می‌شود.
- محدودیت درخواست کد/فاصله ارسال مجدد و انقضا از تنظیمات موجود احراز هویت باقی می‌مانند.
- خطاهای نبود اعتبار، کلید نامعتبر، الگوی تأییدنشده و محدودیت نرخ مدیریت می‌شوند؛ متن خام پاسخ/URL حاوی کلید وارد لاگ یا خطای کاربر نمی‌شود.
- برای بیش از یک replica، سهمیه provider فعلاً در هر فرایند است؛ محدودیت مشترک نیازمند تکمیل زیرساخت جداست.

## وضعیت تکمیل

تست‌های adapter با HTTP mock هستند؛ تست واقعی حساب، الگو و تحویل با کلید مالک هنوز انجام نشده است. ثبت سرویس و تنظیم کلید به معنی اثبات تحویل واقعی نیست.
